# Shopping List API

A REST API for managing a shopping list — add items, view them, update their name/quantity/purchased status, and remove them. Built with **Node.js** and **TypeScript** using only the built-in `http` module.

## Tech Stack

- Node.js (built-in `http` module for the server, no framework)
- TypeScript
- In-memory data store (a plain array — data resets when the server restarts)
- [`tsx`](https://github.com/privatenumber/tsx) for running TypeScript directly in development

## Requirements

- Node.js 18 or newer
- npm 9 or newer

## Getting Started

### 1. Install dependencies

```bash
npm install
```

### 2. Run in development (auto-restarts on file changes)

```bash
npm run dev
```

### 3. Or build and run the compiled JavaScript

```bash
npm run build
npm start
```

By default the server listens on **port 3000**. Set the `PORT` environment variable to use a different port:

```bash
PORT=4000 npm run dev
```

You should see:

```
Shopping List API listening on http://localhost:3000
```

## Data Model

Shopping list item has this shape:

```ts
interface Item {
  id: string;           // UUID, generated by the server
  name: string;
  quantity: number;     // must be a positive number
  purchased: boolean;   // defaults to false if not provided
  createdAt: string;    // ISO 8601 timestamp
  updatedAt: string;    // ISO 8601 timestamp, updated on every PUT
}
```

## Response Shape

Every response is JSON with a consistent envelope, so client code can check `success` without needing to guess the shape per-endpoint.

**Success:**

```json
{
  "success": true,
  "data": { }
}
```

`data` is either a single item object, or an array of items for `GET /items`. `DELETE` returns no body at all (`204 No Content`).

**Error:**

```json
{
  "success": false,
  "error": {
    "message": "\"name\" is required.",
    "code": "BAD_REQUEST"
  }
}
```

`code` is one of `BAD_REQUEST`, `NOT_FOUND`, or `INTERNAL_ERROR`.

## Testing the API with Postman

### Step 1 — Install Postman

Download from [postman.com/downloads](https://www.postman.com/downloads/) if you don't have it, install, and open it. You can skip signing in / creating an account if it prompts — there's usually a "skip" or "guest" option.

### Step 2 — Make sure your server is running

In your terminal:

```powershell
npm run dev
```

Leave that window open and running in the background.

### Step 3 — Create your first request (GET all items)

1. Click the **+** tab (or "New" → "HTTP Request") to open a new request tab.
2. In the dropdown on the left of the URL bar, make sure it says **GET**.
3. In the URL bar, type:
   ```
   http://localhost:3000/items
   ```
4. Click the blue **Send** button.
5. You should see in the response panel below:
   ```json
   {
       "success": true,
       "data": []
   }
   ```
   with status **200 OK** shown near the top right of the response.

If you see that — it's working. ✅

### Step 4 — Create an item (POST)

1. Click **+** again for a new tab.
2. Change the method dropdown from GET to **POST**.
3. URL: `http://localhost:3000/items`
4. Just below the URL bar, click the **Body** tab.
5. Select the **raw** radio button.
6. On the right side of that same row, there's a dropdown (probably says "Text") — change it to **JSON**.
7. In the big text box, paste:
   ```json
   {
     "name": "Milk",
     "quantity": 2
   }
   ```
8. Click **Send**.
9. You should get **201 Created** and a response like:
   ```json
   {
       "success": true,
       "data": {
           "id": "0a11c30c-96c3-49ff-81d6-c7a47808d969",
           "name": "Milk",
           "quantity": 2,
           "purchased": false,
           "createdAt": "...",
           "updatedAt": "..."
       }
   }
   ```

Copy that `id` value — highlight it and Ctrl+C. You'll need it for the next steps.

### Step 5 — Get that one item (GET by id)

1. New tab → **GET**
2. URL: `http://localhost:3000/items/PASTE_YOUR_ID_HERE`
3. Send → should return `200 OK` with that single item.

### Step 6 — Update it (PUT)

1. New tab → **PUT**
2. URL: `http://localhost:3000/items/PASTE_YOUR_ID_HERE`
3. Body tab → raw → JSON, paste:
   ```json
   {
     "quantity": 3,
     "purchased": true
   }
   ```
4. Send → `200 OK`, and the response should show `"quantity": 3, "purchased": true` now.

### Step 7 — Delete it (DELETE)

1. New tab → **DELETE**
2. URL: `http://localhost:3000/items/PASTE_YOUR_ID_HERE`
3. Send → should show **204 No Content** with an empty body.

### Step 8 — Try the error cases (for your test documentation)

1. New tab → **POST** → `http://localhost:3000/items` → Body raw/JSON:
   ```json
   {}
   ```
   Send → should get **400 Bad Request** with a message like `"name" is required.`

2. New tab → **GET** → `http://localhost:3000/items/doesnotexist` → Send → should get **404 Not Found**.

## API Endpoints

### `GET /items`

Returns every item currently on the list.

**Response — `200 OK`**
```json
{
  "success": true,
  "data": [
    {
      "id": "0a11c30c-96c3-49ff-81d6-c7a47808d969",
      "name": "Milk",
      "quantity": 2,
      "purchased": false,
      "createdAt": "2026-09-05T23:03:38.603Z",
      "updatedAt": "2026-09-05T23:03:38.603Z"
    }
  ]
}
```

---

### `GET /items/:id`

Returns a single item by its id.

**Response — `200 OK`** (item found) — same shape as one item above, but `data` is a single object, not an array.

**Response — `404 Not Found`** (no item with that id)
```json
{
  "success": false,
  "error": { "message": "No item found with id \"abc123\".", "code": "NOT_FOUND" }
}
```

---

### `POST /items`

Creates a new item.

**Request body**
```json
{
  "name": "Milk",
  "quantity": 2,
  "purchased": false
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `name` | string | Yes | Must be non-empty after trimming whitespace |
| `quantity` | number | Yes | Must be a positive number |
| `purchased` | boolean | No | Defaults to `false` |

**Response — `201 Created`**
```json
{
  "success": true,
  "data": {
    "id": "0a11c30c-96c3-49ff-81d6-c7a47808d969",
    "name": "Milk",
    "quantity": 2,
    "purchased": false,
    "createdAt": "2026-09-05T23:03:38.603Z",
    "updatedAt": "2026-09-05T23:03:38.603Z"
  }
}
```

**Response — `400 Bad Request`** — missing/invalid field, e.g.:
```json
{
  "success": false,
  "error": { "message": "\"quantity\" must be a positive number.", "code": "BAD_REQUEST" }
}
```

---

### `PUT /items/:id`

Updates an existing item. Any combination of `name`, `quantity`, and `purchased` can be sent — at least one is required.

**Request body (example — mark as purchased and update quantity)**
```json
{
  "quantity": 3,
  "purchased": true
}
```

**Response — `200 OK`** — the full updated item, with `updatedAt` refreshed.

**Response — `400 Bad Request`** — no fields provided, or a provided field has the wrong type.

**Response — `404 Not Found`** — no item exists with that id.

---

### `DELETE /items/:id`

Deletes an item.

**Response — `204 No Content`** — item deleted, no response body.

**Response — `404 Not Found`** — no item exists with that id.

---

## Error Handling

Validation and lookup errors are thrown as a typed `ApiError` from anywhere in the controller/validation code (`src/utils/http.ts`), and caught in one place — the request handler in `server.ts`. This means every route reports failures the same way, without individually formatting error responses:

| Status | When |
|---|---|
| `400` | Malformed JSON body, missing required field, or a field with the wrong type |
| `404` | Item id doesn't exist, or the requested route doesn't exist at all |
| `405` | A recognized route (`/items` or `/items/:id`) called with an unsupported HTTP method |
| `500` | Any unexpected/unhandled error (logged to the server console for debugging) |

## Testing with Postman (or curl)

Import these requests into Postman, or run them directly with curl. Base URL: `http://localhost:3000`.

```bash
# Get all items
curl http://localhost:3000/items

# Create an item
curl -X POST http://localhost:3000/items \
  -H "Content-Type: application/json" \
  -d '{"name":"Milk","quantity":2}'

# Get one item (replace :id with a real id from the create response)
curl http://localhost:3000/items/:id

# Update an item
curl -X PUT http://localhost:3000/items/:id \
  -H "Content-Type: application/json" \
  -d '{"quantity":3,"purchased":true}'

# Delete an item
curl -X DELETE http://localhost:3000/items/:id
```

## Known Limitations

- **Data is in-memory only** — restarting the server clears the entire list. This is intentional per the project spec (Sprint 2: "Store items in memory"); swapping in a real database or file-based persistence would only require changing `src/models/item.ts`.
- No authentication — every request can read/write every item, since the spec doesn't call for multi-user support.
